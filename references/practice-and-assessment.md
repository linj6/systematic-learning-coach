# 实践、证据与掌握度评估规范

## 一、实践验证流程

**定义问题与可证伪预测 → 选择最小环境、数据及控制变量 → 执行或观察 → 保存原始输出 → 与预测对比 → 解释差异 → 记录局限与复现方法。**

不得编造日志、压测数值、截图、资料来源或实验成功记录。

## 教学实验设计与人工验收标准

教学实验的价值在于让学习者**亲自操作、观察现象、理解因果**；能运行不等于适合教学。

### 设计原则

- 一次只验证一个核心机制，不混合多个尚未学习的实验。
- 代码入口明确、调用链短、命名直观；避免不必要的抽象层、反射调度、复杂状态机和自动化黑盒。
- 环境准备与实验业务分离：Docker Compose 可启动依赖服务，业务代码尽量支持 IDE 独立运行和断点调试。
- 提供可手动触发的入口，如 HTTP 接口、main 方法或简单测试方法。
- 日志应对应每一步操作；适用时说明管理后台、数据库和指标界面应出现什么变化。
- 故障通过显式参数或开关控制，便于成功、失败、重试、重置等情景复现。
- 先实现公共环境与实验 A，人工验收后再决定是否实现 B/C；不要一次性生成全部。
- 自动化测试可以辅助验证，但不能取代人工观察路径。

### 实验交付清单

1. **目标与预测**：要验证什么，预计看到什么。
2. **代码结构**：关键类、入口和调用路径。
3. **环境准备**：依赖、版本、启动步骤。
4. **人工操作**：逐步写明要启动、点击、请求或执行什么。
5. **观察位置**：对应的 IDE Console 日志、管理后台、数据库记录或监控指标。
6. **实际结果**：只填写确实执行和观察到的证据，不以预测冒充。
7. **重复与清理**：如何复跑、恢复环境和清除测试数据。
8. **人工验收**：学习者是否看懂代码、是否能独立操作、是否能解释观察到的现象。

## 二、证据状态标记

- **理论预测**：根据原理推导的预期结果，尚未实际观察。
- **历史重建**：依据既有笔记、日志或记录进行推断，并非本次重新执行。
- **实际执行**：确实运行过实验，需注明环境、条件和覆盖范围。
- **人工观察**：在明确条件下人工查看到的现象。
- **外部资料**：由第三方来源报告的结果，需保留来源与局限。

明确区分相关性与因果性、模型假设与已证实事实。金融投资领域的回测还应考虑前视偏差、幸存者偏差、交易成本和样本外验证；历史收益不能证明未来收益。

## 三、掌握度等级

- **L1 认识**：能够识别概念、目的和主要组成。
- **L2 理解**：能够独立解释机制、执行顺序、原因和适用条件。
- **L3 应用**：能够分析新案例，或设计可行方案并说明取舍。
- **L4 验证与诊断**：能够在真实约束下进行验证、排障或批判性评估。

等级属于基于当前证据的阶段判断。记录评估日期、依据，以及回答是否依赖提示。一次回答正确不足以认定 L4 或长期记忆稳固。

## 四、优先级与停止条件

- **P0**：支撑知识体系的核心基础，优先学习。
- **P1**：与目标密切相关的重要扩展，按需深入。
- **P2**：低优先级细节，记录后暂缓。

当学习者达到目标等级、修复关键误解、完成必要验证时，即可结束单元。若实验成本过高，应明确记录哪些结论尚未验证，而不是默认成立。

## 五、长期保持（待验证）

建议使用主动回忆，安排短期、跨周和跨月复习，并根据实际遗忘情况调整。记录哪些方式改善了记忆效果；不要把固定间隔描述为已在该学习者身上得到实证验证。
